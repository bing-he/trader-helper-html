This note documents the main NYMEX Curve Analyst definitions directly from the current code. It is meant to be a hidden audit trail for how the report is built. Cents are written as ¢ here rather than c; for example, 10¢ means $0.10/MMBtu.
A. Basic definitions
Season buckets
  • What it means: The report groups months into winter, summer, and shoulder so seasonal comparisons use economically similar periods.
  • How it is computed: A month is mapped through the season bucket function in market-structure analytics.
Formula / rules: winter = {Nov, Dec, Jan, Feb, Mar}; summer = {Jun, Jul, Aug, Sep}; shoulder = {Apr, May, Oct}.
Interpretation: Seasonal features compare against peers in the same bucket rather than against every date in history.
DeliverySeason
  • What it means: The season of the resolved nearby delivery month, not the trade date.
  • How it is computed: The code resolves the front month for each row, converts that month to a season bucket, and stores it as DeliverySeason.
Formula / rules: DeliverySeason_t = season(front_month_t).
Interpretation: This is the peer set used by prompt seasonal z, strip seasonal z, and spread seasonal z.
TradeSeason
  • What it means: The season of the calendar date when the row was traded.
  • How it is computed: The trade date month is bucketed with the same winter / summer / shoulder mapping.
Formula / rules: TradeSeason_t = season(Date_t.month).
Interpretation: TradeSeason is descriptive context; DeliverySeason is the more important bucket for prompt / strip / spread seasonal comparisons.
Seasonal lookback settings
  • What it means: The default seasonal comparison horizon is 7 years, with preferred and fallback sample-size rules.
  • How it is computed: Seasonal z-scores first try prior same-season observations inside the last 7 years. If that sample is too small, they fall back to all prior same-season rows.
Formula / rules: lookback_years = 7; preferred_min_obs = 80; fallback_min_obs = 40; std uses ddof = 0.
Interpretation: This makes the metric more stable than a very thin seasonal peer set while still prioritizing recent history when enough data exists.
12M strip
  • What it means: The average level of the front 12 listed forward tenors.
  • How it is computed: The report averages FWD_00 through FWD_11 for each row, using whichever of those columns are present and numeric.
Formula / rules: Strip12_t = mean(FWD_00, FWD_01, ..., FWD_11).
Interpretation: This is the report's broad curve level measure, less noisy than prompt alone.
Front3 / Back3 / Spread
  • What it means: Front3 is the nearby end of the curve, Back3 is the deferred comparison bucket, and Spread measures front-versus-back tightness.
  • How it is computed: Front3 is the mean of FWD_00 to FWD_02. Back3 is the mean of the absolute delivery months at front + 12, +13, +14 months, with a fallback to the mean of FWD_11 to FWD_13 when needed. Spread is Front3 minus Back3.
Formula / rules: Front3_t = mean(FWD_00, FWD_01, FWD_02); Back3_t = mean(front+12, +13, +14 delivery months); Spread_t = Front3_t - Back3_t.
Interpretation: Positive spread usually means the front is richer than deferred; negative spread means the back is richer than the front.
Winter premium
  • What it means: A simple cross-season richness measure inside the front 12 tenors.
  • How it is computed: For each row, the code averages all winter delivery tenors inside the first 12 forward months and subtracts the average of the non-winter tenors.
Formula / rules: WinterPremium_t = mean(winter tenors in FWD_00:11) - mean(non-winter tenors in FWD_00:11).
Interpretation: A higher winter premium means winter-delivery gas is pricing richer than the rest of the front-year strip.
Cash confirmation basics
  • What it means: Cash panels compare Henry cash to prompt and strip pricing to judge whether physical pricing confirms or diverges from the futures read.
  • How it is computed: Cash analytics merge Henry cash with forward history, then compute basis, rolling z-scores, rolling percentiles, two rolling lead-lag correlation passes (~42 and ~126 sessions), and shock beta.
Formula / rules: basis0 = Henry - FWD_00; basis12 = Henry - Strip12; cash_vol_20d = rolling std of 1d cash returns annualized to %. In this note, 10¢ means $0.10/MMBtu.
Interpretation: Positive basis means cash is over futures; negative basis means cash is under futures.
B. Feature definitions
Prompt seasonal z score (`prompt_vs_seasonal_z`)
  • What it means: How rich or cheap FWD_00 is versus prior rows in the same DeliverySeason bucket.
  • How it is computed: The code compares today's FWD_00 to earlier rows with the same DeliverySeason, prefers the last 7 years of that bucket, then falls back to all prior same-season rows if needed.
Formula / rules: z_t = (FWD_00_t - mean(hist)) / std(hist), where hist is prior same-DeliverySeason rows; preferred_min_obs = 80; fallback_min_obs = 40; ddof = 0.
Interpretation: Positive means prompt is rich versus the same delivery-season regime; negative means it is cheap.
Back3 seasonal z score (`scope_deferred_z`)
  • What it means: How rich or cheap deferred pricing is versus prior rows in the same DeliverySeason bucket.
  • How it is computed: Narrative context takes the Back3 series and applies the same seasonal z-score logic used for prompt, strip, and spread seasonal comparisons.
Formula / rules: scope_deferred_z_t = (Back3_t - mean(hist)) / std(hist), where hist is prior same-DeliverySeason rows under the 7y / 80 / 40 rules.
Interpretation: Positive means deferred gas is rich versus the same delivery-season regime; negative means it is cheap.
12M strip rolling z score (`strip_z_1y`)
  • What it means: How stretched the 12M strip is versus its own trailing history.
  • How it is computed: The strip series uses a rolling z-score over a 365-session window with a 60-session minimum.
Formula / rules: strip_z_1y_t = rolling_zscore(Strip12, window = 365, min_periods = 60).
Interpretation: This is the report's rolling strip stretch diagnostic; it is different from the seasonal strip z-score.
Seasonal strip z score (`strip_z_season`)
  • What it means: How rich or cheap the 12M strip is versus prior rows in the same DeliverySeason bucket.
  • How it is computed: The strip uses the common seasonal z-score helper with the same 7-year lookback and min-observation rules used elsewhere.
Formula / rules: strip_z_season_t = (Strip12_t - mean(hist)) / std(hist), where hist is prior same-DeliverySeason rows under the 7y / 80 / 40 rules.
Interpretation: This is usually the more stable regime input for strip richness than the rolling z-score alone.
Spread rolling z score (`spread_z`)
  • What it means: How stretched the Front3 minus Back3 spread is versus its own trailing history.
  • How it is computed: The spread series is passed through the rolling z-score helper with a 365-session window and a 60-session minimum.
Formula / rules: spread_z_t = rolling_zscore(Spread, window = 365, min_periods = 60).
Interpretation: Positive means front richness versus back is elevated versus recent history; negative means the opposite.
Seasonal spread z score (`spread_z_season`)
  • What it means: How rich or cheap the spread is versus prior rows in the same DeliverySeason bucket.
  • How it is computed: The same seasonal z-score helper is applied to the spread series with DeliverySeason peers.
Formula / rules: spread_z_season_t = (Spread_t - mean(hist)) / std(hist), with hist chosen under the same 7y / 80 / 40 same-season rules.
Interpretation: This is the preferred regime input for nearby abundance / scarcity when enough same-season history exists.
Percentile rank / pctile
  • What it means: An empirical ranking of today's value inside a sample rather than a z-score.
  • How it is computed: The helper computes the share of observations less than or equal to the current value. Some places keep it in 0 to 1 form, while dashboard displays usually multiply by 100.
Formula / rules: percentile_rank(sample, x) = mean(sample <= x); displayed pctile = percentile_rank * 100.
Interpretation: A 90th pctile means today's value is above about 90% of the reference sample.
Prompt same-month percentile (`prompt_month_pct`)
  • What it means: A month-of-year percentile for prompt, separate from DeliverySeason z-scores.
  • How it is computed: For each row, the code compares FWD_00 to earlier prompt observations from the same calendar month and requires at least 5 prior observations.
Formula / rules: prompt_month_pct_t = percentile(FWD_00_t within prior prompt rows where month(i) = month(t)); min_hist = 5.
Interpretation: This is a simpler seasonal percentile, useful as supporting context when the full z-score logic is harder to interpret quickly.
Calendar-date percentile
  • What it means: A same-day-of-year percentile used in the narrative for prompt and strip seasonality callouts.
  • How it is computed: The function compares the as-of value to prior observations on the same calendar day-of-year and requires at least 5 prior matches.
Formula / rules: calendar_date_pct_t = percentile(x_t within prior rows where day_of_year(i) = day_of_year(t)); min_hist = 5.
Interpretation: This is narrower than DeliverySeason. It answers 'how unusual for this exact calendar slot?' rather than 'how unusual for this season bucket?'
Cash confirmation score
  • What it means: A signed shortcut signal telling the dashboard whether cash is confirming, conflicting, or neutral versus the futures read.
  • How it is computed: The score uses basis0_z first, then checks whether 5-day cash returns and lead-lag correlation support the sign of the basis move.
Formula / rules: Returns +1 when basis0_z is high and cash is supportive, -1 when basis0_z is low and cash is weak, else 0; thresholds include basis0_z >= +1.5 or <= -1.5 and fallback checks around ±0.75 when best_corr >= 0.25 and best_lag <= 0.
Interpretation: Positive supports tighter cash / stronger physical confirmation; negative supports weaker cash / looser physical confirmation.
Cash lead-lag and shock beta
  • What it means: These measure whether cash tends to lead prompt and how strongly prompt responds to daily cash shocks.
  • How it is computed: The code searches lags -5 to +5 on 1-day returns, picks the lag with the largest absolute rolling correlation, and fits a simple slope between cash and prompt daily returns for the beta chart.
Formula / rules: Long-window best_lag / best_corr use rolling corr over 126 sessions (min_periods = 60). A second pass uses ~2 calendar months of sessions (42 trading days, min_periods = 25) for the same lag search; narrative compares them so a stronger |r| in the short window when signs agree reads as a tighter recent physical–prompt link. shock_beta is the OLS slope of prompt_ret_1d on cash_ret_1d over the latest 126 valid rows when at least 30 points exist.
Interpretation: Negative best_lag means cash tends to lead prompt; a larger positive beta means prompt tends to move more for a given daily cash move.
C. Regime definitions
Market state
  • What it means: The figure notes use short market-state labels so you can see the current condition before reading the detailed metrics.
  • How it is computed: Market state is taken from the current regime fields and trader-facing state labels: for example regime_strip, regime_spread, regime_seasonality, regime_basis, regime_velocity, or directional bias / confidence in the analog section.
Formula / rules: Examples: strip = normal; spread = scarcity; seasonality = cheap_for_date; basis = cash_tight; velocity = flattening.
Interpretation: Think of market state as the headline label, with the note bullets explaining why the model put the market in that state.
Regime strip (`regime_strip`)
  • What it means: A three-state strip richness bucket.
  • How it is computed: The regime uses strip_z_season when available, otherwise strip_z_1y.
Formula / rules: low if z <= -0.75; normal if -0.75 < z < +0.75; high if z >= +0.75.
Interpretation: This is the main high / normal / low level classification for the 12M strip.
Regime spread (`regime_spread`)
  • What it means: A three-state nearby tightness bucket.
  • How it is computed: The regime uses spread_z_season when available, otherwise spread_z.
Formula / rules: abundant if z <= -0.75; neutral if -0.75 < z < +0.75; scarcity if z >= +0.75.
Interpretation: Scarcity means the front is rich versus the back; abundant means the front is cheap versus the back.
Regime seasonality (`regime_seasonality`)
  • What it means: A three-state prompt seasonal richness bucket.
  • How it is computed: The regime is built directly from prompt_vs_seasonal_z.
Formula / rules: cheap_for_date if z <= -0.75; normal_for_date if -0.75 < z < +0.75; rich_for_date if z >= +0.75.
Interpretation: Because prompt_vs_seasonal_z now uses DeliverySeason peers, 'for date' here really means rich / cheap for the current delivery-season setup.
Regime basis (`regime_basis`)
  • What it means: A three-state cash-vs-prompt basis bucket.
  • How it is computed: The regime is built from basis0_z.
Formula / rules: prompt_tight if basis0_z <= -1.0; normal_basis if -1.0 < basis0_z < +1.0; cash_tight if basis0_z >= +1.0.
Interpretation: Negative basis z means cash is cheap to prompt; positive basis z means cash is rich to prompt.
Regime volatility (`regime_vol`)
  • What it means: A simple volatility state for Henry cash.
  • How it is computed: The code compares cash_vol_20d to a rolling 80th percentile cutoff over max(60, cash_lookback) sessions.
Formula / rules: high_vol if cash_vol_20d >= rolling 80th percentile cutoff; otherwise normal_vol; unknown when vol is not available.
Interpretation: This separates calm tape from unusually noisy cash behavior.
Regime velocity (`regime_velocity`)
  • What it means: A slope / shape state describing whether the curve is steepening, flattening, or flat.
  • How it is computed: The regime uses delta20_slope when available, otherwise curve_delta_20d, then buckets through the velocity-state helper.
Formula / rules: steepening if value > +0.02; flattening if value < -0.02; flat otherwise.
Interpretation: This is the mechanical state label that feeds broader curve-shape interpretation.
Composite regime
  • What it means: A compact joined label summarizing the main regime states.
  • How it is computed: The report concatenates regime_strip, regime_spread, regime_vol, and regime_velocity into one slash-separated string.
Formula / rules: composite_regime = regime_strip / regime_spread / regime_vol / regime_velocity.
Interpretation: It is mainly a compact snapshot for downstream grouping and quick reading rather than a new model feature with its own formula.
D. State labels
Nearby labels
  • What it means: Trader-facing text that summarizes whether prompt stress is visible in the nearby spread.
  • How it is computed: The display layer classifies the spread using spread z / percentile plus cash confirmation context.
Formula / rules: nearby_tight if spread_z > +1.0 and cash_confirmation_score > +0.5; nearby_loose if spread_z < -1.0 and cash_confirmation_score < -0.5; otherwise nearby balanced. If z is unavailable, percentile fallbacks use 85 / 15 with the same cash-confirmation sign filter.
Interpretation: The user sees labels such as 'Nearby tight / prompt stress visible' or 'Nearby balanced / no prompt stress.'
Curve scope labels
  • What it means: A trader-facing description of whether the move is front-end, deferred, broad, or balanced.
  • How it is computed: The classifier compares the absolute size of prompt stretch and deferred stretch.
Formula / rules: front_end_story if |prompt_z| > 1.0 and |deferred_z| < 0.5; deferred_story if |prompt_z| < 0.5 and |deferred_z| > 1.0; curve_wide_repricing if both > 1.0; else balanced_overall.
Interpretation: This is where labels like 'Mostly deferred move' or 'Curve broadly balanced' come from.
Seasonality labels
  • What it means: A simplified prompt / strip seasonality read shown in the display layer.
  • How it is computed: The classifier looks at front and strip calendar-date percentiles rather than the DeliverySeason z-score.
Formula / rules: stronger_than_seasonal if either percentile > 80; weaker_than_seasonal if either percentile < 20; otherwise seasonally_normal.
Interpretation: This is a percentile-based headline read, not the same calculation as prompt_vs_seasonal_z.
Velocity labels
  • What it means: A display-layer interpretation of whether the recent move looks outright, flattening, steepening, or localized.
  • How it is computed: The code builds four scores from 5-day and 10-day level / slope / curvature moves and takes the maximum score.
Formula / rules: Scores use weighted clips of curve_delta_5d, front3_change_5d, delta10_slope, delta10_curvature, delta10_level, kink_z, and shape alignment; the winning score becomes one of outright_move / flattening / steepening / localized_shape_move.
Interpretation: This is why the report can say 'Curve flattening' even when several curve dimensions moved at once: it is the strongest scoring explanation, not the only thing that changed.
E. Prediction and analog features
Curve factors
  • What it means: Compact level / slope / curvature summaries of the front 12 forward tenors.
  • How it is computed: The factor builder averages FWD_00:02, FWD_03:08, and FWD_09:11, then derives curve-wide level, slope, and curvature.
Formula / rules: front_factor = mean(FWD_00:02); belly_factor = mean(FWD_03:08); back_factor = mean(FWD_09:11); level = mean(FWD_00:11); slope = back - front; curvature = 2 * belly - front - back.
Interpretation: These provide a compact shape representation for forecasts and analog distance ranking.
Delta features
  • What it means: Multi-horizon changes in level, slope, and curvature.
  • How it is computed: The factor frame computes 5-day, 10-day, and 20-day differences for the base curve factors.
Formula / rules: deltaN_feature_t = feature_t - feature_(t-N), for N in {5, 10, 20}.
Interpretation: These features help the report decide whether a move is fresh, extended, steepening, flattening, or localized.
Analog distance features
  • What it means: The numeric feature set used to rank historical analogs by similarity.
  • How it is computed: The analog engine compares current conditions with historical rows using standardized distances across a selected set of numeric columns.
Formula / rules: Key candidates include spread_z_season, strip_z_season, prompt_vs_seasonal_z, kink_z, basis0_z, cash_vol_20d, winter_premium, delta10_level, delta10_slope, delta10_curvature, spread_z, strip_z_1y, and shape_20d.
Interpretation: The analog engine does not rely on just one feature; it combines seasonal stretch, curve shape, basis, vol, and recent change features.
Regime matching for analogs
  • What it means: Historical candidates get a regime-match bonus before final distance ranking.
  • How it is computed: The engine checks regime_strip, regime_spread, regime_season, regime_basis, regime_vol, and regime_shape against the current row, keeps looser filters when necessary, and then rewards higher regime agreement.
Formula / rules: Candidates first prefer match_score >= 3, then >= 2, then >= 1 if needed; effective_distance = euclidean_distance / (1 + 0.20 * match_score).
Interpretation: This keeps analogs closer to the same market state instead of matching only on raw numeric distance.
Analog selection rules
  • What it means: How many analogs are chosen and how clustered they are allowed to be in time.
  • How it is computed: After regime filtering and distance scoring, the engine selects spaced dates so near-duplicate historical episodes do not dominate the analog set.
Formula / rules: Defaults are top_k = 10, anchor_horizon = 40, min_spacing_sessions = 20.
Interpretation: The selected analog set is intended to be diverse enough to be informative while still representing the closest historical matches.
Fixed-contract outcomes
  • What it means: Forward return targets are built from a fixed contract so horizons are comparable through time.
  • How it is computed: The outcomes engine anchors to the contract that will be front-month 40 trading days ahead, then measures 2w / 4w / 8w moves on that fixed contract.
Formula / rules: Default horizons are 2w = 10 sessions, 4w = 20 sessions, 8w = 40 sessions.
Interpretation: This avoids mixing contract roll effects into the analog and forecast target definitions.
Factor quantile forecasts
  • What it means: A linear forecast model that turns current features into p25 / p50 / p75 outcome bands.
  • How it is computed: The forecast step joins feature inputs to fixed-contract outcomes, standardizes features, fits a linear model, and then uses residual quantiles to translate the central forecast into bands.
Formula / rules: Core inputs include level, slope, curvature, spread_z, kink_z, and basis0_z when present.
Interpretation: This is why the report can show forecast ranges instead of a single point estimate only.
